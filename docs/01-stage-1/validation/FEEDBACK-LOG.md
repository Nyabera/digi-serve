## Entry schema

| Field | Rule |
|---|---|
| ID | immutable `FB-YYYY-NNN` |
| date/source/context | role or anonymous applicant cohort; no unnecessary PII |
| acceptance/route reference | exact AC ID/route/command where applicable |
| observation | factual statement separated from proposed solution |
| severity | critical/high/medium/low with defined safety/acceptance impact |
| evidence | privacy-safe test/case/research reference |
| owner/state | `NEW`, `TRIAGED`, `DECISION_REQUIRED`, `PLANNED`, `RESOLVED`, `DECLINED` |
| disposition | linked decision/change/test; never silent scope change |

## Current entries

No synthetic-test, user-research or pilot feedback has been supplied yet. This is intentionally empty; example complaints must not be presented as real evidence.

## Handling rules

Remove unnecessary personal data; restrict sensitive submissions; acknowledge safety/security reports promptly; merge duplicates without deleting originals; never mark resolved without verification. Critical security/data/outcome issues trigger the incident/stop process, not ordinary backlog triage.
