# FAIDIA Stage 1 — Validation Plan

**Status:** READY_FOR_PRODUCT_OWNER_REVIEW  
**Version:** 0.1  
**Last updated:** 2026-07-14  
**Authority:** Stage 0 purpose/success criteria and `PILOT-PLAN.md`

## 1. Validation questions

1. Can every approved Transcript Request be located with a clear owner/status/history?
2. Can applicants understand progress and required actions without repeated informal enquiry?
3. Can Records, Finance and Registrar coordinate the complete approved path inside FAIDIA?
4. Are outcomes/completion/reopening auditable and permission-correct?
5. Does the product reduce lost requests and off-platform coordination without creating unacceptable effort/risk?

## 2. Evidence matrix

| Question | Quantitative evidence | Qualitative evidence |
|---|---|---|
| traceability | requests with full required audit sequence; unresolved/unowned count | staff reconstruction exercise |
| applicant clarity | tracking visits, correction response, status enquiries per case | short applicant questionnaire/interview |
| coordination | handoff acceptance/completion, processing durations, off-platform contacts logged | weekly Records/Finance/Registrar review |
| outcome control | issuance/download/collection/manual-close/reopen evidence completeness | exception case review |
| operational value | completion rate/time, overdue/correction/lost-request counts vs baseline | staff effort/usability feedback |

## 3. Measurement rules

Define cohort, period, timezone, inclusion/exclusion and denominator before calculation. Use stored domain facts for workflow measures. Calls, email, WhatsApp, paper and “lost request” reductions require baseline plus explicit staff/applicant capture; absence of an app event is not proof of reduction. Small pilot results are descriptive, not statistically generalizable.

## 4. Review cadence

Synthetic acceptance review before pilot; daily safety/operations during pilot; weekly structured staff review; applicant feedback after meaningful completion/correction; final review after reconciliation. Record raw findings with privacy-safe references, owner, severity and disposition.

## 5. Decision framework

- `PROCEED`: safety/acceptance pass and evidence supports the thesis;
- `PROCEED_WITH_CONDITIONS`: no critical safety failure; bounded improvements with owners/dates;
- `REVISE_AND_RETEST`: material workflow/usability/value gap;
- `STOP`: security/data/outcome-authority failure or insufficient institutional support.

Thresholds must be approved in the pilot authorization after baseline discovery; this draft does not invent them.
